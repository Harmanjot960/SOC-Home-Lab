# Useful SPL Queries

This document contains commonly used Splunk Search Processing Language (SPL) queries for investigating Windows endpoint activity collected through Sysmon and Windows Event Logs.

---

# 1. Process Creation

### Objective

Identify newly created processes on the endpoint.

```spl
index=sysmon EventID=1
| table _time Image CommandLine ParentImage User
```

**Why it matters**

Shows every process execution along with its parent process and command line, helping identify suspicious activity.

---

# 2. Network Connections

### Objective

Review outbound network connections initiated by processes.

```spl
index=sysmon EventID=3
| table _time Image DestinationIp DestinationPort Initiated
```

**Why it matters**

Useful for identifying unexpected external connections made by applications or malware.

---

# 3. DNS Queries

### Objective

Review DNS requests generated by endpoint processes.

```spl
index=sysmon EventID=22
| table _time Image QueryName
```

**Why it matters**

Helps identify suspicious or malicious domains contacted by processes.

---

# 4. Failed Logon Attempts

### Objective

Identify failed authentication attempts.

```spl
index=wineventlog EventCode=4625
| stats count by Account_Name Source_Network_Address
```

**Why it matters**

Useful for detecting brute-force attacks and unauthorized login attempts.

---

# 5. Successful Logons

### Objective

Review successful user authentication events.

```spl
index=wineventlog EventCode=4624
| stats count by Account_Name
```

**Why it matters**

Provides visibility into successful logins and user activity.

---

# 6. File Creation Events

### Objective

Monitor files created on the endpoint.

```spl
index=sysmon EventID=11
| table _time Image TargetFilename
```

**Why it matters**

Useful for detecting malware dropping payloads or suspicious file creation.

---

# 7. Process Timeline

### Objective

Reconstruct the order of process execution during an investigation.

```spl
index=sysmon EventID=1
| table _time Image CommandLine ParentImage ProcessId
| sort _time
```

**Why it matters**

Helps analysts understand how an attack progressed over time.

---

# 8. Investigate a Suspicious Process

### Objective

Review activity associated with a specific process.

```spl
index=sysmon
| search Image="*powershell.exe"
| table _time EventID CommandLine ParentImage DestinationIp QueryName
```

**Why it matters**

Allows analysts to pivot from a suspicious process and examine related activity.

---

# 9. Correlating Endpoint Activity

### Objective

Correlate process execution, DNS requests, and network connections using the process image.

```spl
index=sysmon
| rex field=_raw "<EventID>(?<EventID>\d+)</EventID>"
| rex field=_raw "<Data Name='Image'>(?<Image>[^<]+)</Data>"
| rex field=_raw "<Data Name='CommandLine'>(?<CommandLine>[^<]+)</Data>"
| rex field=_raw "<Data Name='QueryName'>(?<QueryName>[^<]+)</Data>"
| rex field=_raw "<Data Name='DestinationIp'>(?<DestinationIp>[^<]+)</Data>"
| rex field=_raw "<Data Name='ProcessId'>(?<ProcessId>[^<]+)</Data>"
| search EventID IN (1,3,22)
| stats values(CommandLine) as Command
        values(QueryName) as DNS
        values(DestinationIp) as IP
by Image ProcessId
```

**Why it matters**

Correlates multiple Sysmon events to provide a consolidated view of endpoint activity during an investigation.

---

# 10. Search for Indicators of Compromise (IOC)

### Objective

Search logs for a known malicious IP address or domain.

Example using an IP address:

```spl
index=sysmon
| search "192.168.1.100"
```

Example using a domain:

```spl
index=sysmon
| search "malicious-domain.com"
```

**Why it matters**

Enables rapid hunting for known Indicators of Compromise (IOCs) across collected telemetry.

---

## Summary

These queries provide a foundation for investigating Windows endpoint activity using Splunk and Sysmon. They support common SOC workflows such as process analysis, network investigation, DNS monitoring, authentication review, timeline reconstruction, and threat hunting.
